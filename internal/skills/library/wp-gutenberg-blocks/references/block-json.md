# block.json reference (schema: https://schemas.wp.org/trunk/block.json)

Use `block.json` as the single source of truth; register from PHP (see php-registration-and-render.md), import the same file in JS.

## Canonical full example

```json
{
  "$schema": "https://schemas.wp.org/trunk/block.json",
  "apiVersion": 3,
  "name": "acme/card",
  "version": "1.2.0",
  "title": "Card",
  "category": "design",
  "icon": "id",
  "description": "Teaser card.",
  "keywords": [ "teaser", "box" ],
  "textdomain": "acme",
  "attributes": {
    "heading":   { "type": "rich-text", "source": "rich-text", "selector": "h3", "role": "content" },
    "url":       { "type": "string", "source": "attribute", "selector": "a", "attribute": "href", "role": "content" },
    "mediaId":   { "type": "number" },
    "layout":    { "type": "string", "enum": [ "stack", "row" ], "default": "stack" },
    "isPreview": { "type": "boolean", "role": "local" }
  },
  "providesContext": { "acme/layout": "layout" },
  "usesContext": [ "postId", "postType" ],
  "supports": {
    "html": false,
    "anchor": true,
    "align": [ "wide", "full" ],
    "color": { "background": true, "text": true, "link": true },
    "spacing": { "padding": true, "margin": [ "top", "bottom" ] },
    "typography": { "fontSize": true, "lineHeight": true },
    "interactivity": true
  },
  "selectors": { "root": ".wp-block-acme-card", "typography": ".wp-block-acme-card h3" },
  "styles": [ { "name": "default", "label": "Default", "isDefault": true }, { "name": "outline", "label": "Outline" } ],
  "example": { "attributes": { "heading": "Example", "layout": "row" } },
  "editorScript": "file:./index.js",
  "editorStyle": "file:./index.css",
  "style": "file:./style-index.css",
  "viewScriptModule": "file:./view.js",
  "render": "file:./render.php"
}
```

## Top-level fields

| Field | Since | Notes |
|---|---|---|
| `$schema` | — | Enables IDE validation/autocomplete. Schema now validates `apiVersion` as `const: 3` (WP 6.9+). |
| `apiVersion` | 3 = WP 6.3 | Default 1 when omitted. Always `3` (see deprecations-and-migrations.md for iframe rules). |
| `name` | — | `namespace/slug`, lowercase alnum + dashes, starts with letter. Never rename after release (breaks saved content). |
| `title`, `description`, `keywords` | — | Auto-translated (`_x`) when `textdomain` set. |
| `category` | — | Core: `text`, `media`, `design`, `widgets`, `theme`, `embed`. Custom via `block_categories_all` filter. |
| `icon` | — | Dashicon slug in JSON; pass an SVG element in JS settings to override. |
| `textdomain` | 5.7 | Required for metadata i18n and auto `wp_set_script_translations()` on script fields. |
| `version` | 5.8 | Fallback asset version when no `.asset.php`. Bump for cache busting. |
| `parent` | — | Direct-parent restriction (array of block names). |
| `ancestor` | 6.0 | Allowed anywhere inside listed ancestors. |
| `allowedBlocks` | 6.5 | Restrict children. Pair with `supports.allowedBlocks` (6.9) for user UI. |
| `attributes` | — | See below. |
| `providesContext` / `usesContext` | 5.5 | Map context key → own attribute; consumers list keys. Core keys: `postId`, `postType`, `queryId`, `query`, `termId`, `taxonomy`, … |
| `supports` | — | See table below. |
| `selectors` | 6.3 | Per-feature CSS selectors for global styles; `states` sub-key maps custom states (WP 7.1, see theme-json-and-styles.md). |
| `styles` | — | Block style variations (`is-style-{name}` class). |
| `example` | — | Inserter preview data; `attributes` + `innerBlocks`. Omit to disable preview. |
| `variations` | 5.9; PHP file 6.7 | Array, or `"file:./variations.php"` returning an array (wrap strings in `__()`). |
| `blockHooks` | 6.4 | `{ "core/post-content": "after" }`; positions `before` `after` `firstChild` `lastChild`. |
| `render` | 6.1 | PHP template path; makes block dynamic (core auto-creates `render_callback`). |
| `editorScript` / `script` / `viewScript` | viewScript 5.9 | Classic scripts. Arrays allowed (6.1+). |
| `viewScriptModule` | 6.5 | ES module, front end only. Required for Interactivity API. |
| `editorStyle` / `style` / `viewStyle` | viewStyle 6.5 | Arrays allowed (5.9+). |
| `__experimental` | — | Marks block as part of an experiment; don't use in production plugins. |

### Asset field rules
- `file:./path` = relative to `block.json`. Otherwise string = registered handle / module ID. Arrays may mix both.
- Core reads `*.asset.php` next to each file (generated by `wp-scripts`) for `dependencies` + `version`. Missing asset file → no deps (scripts silently break when `wp-*` globals load late).
- Generated handles: `{namespace}-{slug}-{editor-script|editor-style|script|style|view-script|view-script-module|view-style}`, suffix `-2`, `-3`… for array index > 0. Core blocks: `wp-block-{slug}[-editor|-view][-script-module]`.
- `viewScript` ≠ `viewScriptModule`: classic scripts cannot `import` modules; use `viewScriptModule` for `@wordpress/interactivity` code.
- Frontend block scripts/styles load only when the block renders in block themes (default). Classic themes load them globally unless `add_filter( 'should_load_block_assets_on_demand', '__return_true' )` (WP 6.8+; `should_load_separate_core_block_assets` now only controls splitting `wp-block-library`).
- Every style the block needs in the editor MUST be declared here (or via `enqueue_block_assets`); the canvas is an iframe and admin-page CSS does not reach it.

## Attributes

| Key | Values |
|---|---|
| `type` | `null` `boolean` `object` `array` `string` `rich-text` `integer` `number` (array of types allowed, not with `rich-text`) |
| `source` | `attribute` `text` `html` `rich-text` `raw` `query` `tag` `meta` (**deprecated** → `useEntityProp` / block bindings) |
| `selector` | CSS selector inside block root; omit = root |
| `attribute` | HTML attribute name for `source: attribute` |
| `query` | Sub-schema for `source: query` (array of objects from repeated elements) |
| `enum` | Allowed values; type optional when enum given |
| `default` | Default value; not serialized when equal to default |
| `role` | `content` (editable in contentOnly/pattern/override modes, shown in List View) or `local` (never serialized). Stabilized WP 6.7. |

Rules:
- No `source` → value stored as JSON in the block comment delimiter. Prefer this for config values; use sourced attributes only for user-visible markup content.
- RichText content: `"type": "rich-text", "source": "rich-text", "selector": "…"` (core pattern; value is a `RichTextData` object, stringify with `.toString()` / `String()` when needed).
- Sourced attributes are re-parsed from saved HTML: any `save()` markup change breaks them → add a deprecation.
- Mark every user-content attribute `"role": "content"` (WP 7.0 applies contentOnly to unsynced patterns/template parts; blocks without a content role are hidden in List View and unselectable there). Fallback when no attribute fits: `supports.contentRole: true` (6.9).
- Attributes added by supports (`style`, `backgroundColor`, `textColor`, `gradient`, `fontSize`, `align`, `anchor`, `className`, `metadata`, `textShadow`…) are injected automatically; never declare them yourself.
- `metadata` (auto) carries `name` (pattern overrides / rename), `bindings`, `blockVisibility`, `ignoredHookedBlocks`.

Still-experimental keys used by core (not in schema, may change): `__experimentalBorder`, `typography.__experimentalFontFamily|FontWeight|FontStyle|TextTransform|TextDecoration|LetterSpacing`, `__experimentalDefaultControls`, `__experimentalSkipSerialization`, `__experimentalOnEnter`, `__experimentalSettings`. Using them is the only way to get border/font-family UI today; expect renames.

Serialization: supports that add `style` output inline styles/classes via `useBlockProps` / `useBlockProps.save()` / `get_block_wrapper_attributes()`. Use `__experimentalSkipSerialization: true` (per feature or array of sub-features) to apply them to an inner element yourself.

# PHP: registration, dynamic rendering, assets, PHP-only blocks

## Register (always on `init`)

| Need | API | Since |
|---|---|---|
| One block | `register_block_type( __DIR__ . '/build/card' )` (folder or `block.json` path) | 5.5 (path form) |
| Many blocks, fast | `wp_register_block_types_from_metadata_collection( $dir, $manifest )` | 6.8 |
| Many blocks, need custom `$args` per block | `wp_register_block_metadata_collection( $dir, $manifest )` then `register_block_type( $dir . '/slug', $args )` | 6.7 |
| No block.json, PHP-only | `register_block_type( 'ns/name', [ …, 'supports' => [ 'autoRegister' => true ] ] )` | 7.0 |

Manifest = `build/blocks-manifest.php`, generated by `wp-scripts build --blocks-manifest` (see build-tooling.md). It avoids reading/decoding every `block.json` per request.

```php
add_action( 'init', function () {
	$dir      = __DIR__ . '/build';
	$manifest = $dir . '/blocks-manifest.php';
	if ( function_exists( 'wp_register_block_types_from_metadata_collection' ) ) { // WP 6.8+
		wp_register_block_types_from_metadata_collection( $dir, $manifest );
		return;
	}
	if ( function_exists( 'wp_register_block_metadata_collection' ) ) {          // WP 6.7
		wp_register_block_metadata_collection( $dir, $manifest );
	}
	foreach ( array_keys( require $manifest ) as $slug ) {                       // ≤ 6.6
		register_block_type( "{$dir}/{$slug}" );
	}
} );
```
Drop the fallbacks when `Requires at least` ≥ 6.8. Collection path must be a plugin/theme subfolder, never `WP_PLUGIN_DIR`/theme root itself (`_doing_it_wrong` + `false`; extend roots via `wp_allowed_block_metadata_collection_roots`, 6.7.2). Missing manifest → `false`.

Override/extend metadata at registration: `register_block_type( $path, [ 'render_callback' => 'acme_render', 'variation_callback' => 'acme_variations' ] )` (`variation_callback` 6.5: build variations lazily, only when requested). Filters: `block_type_metadata` (raw metadata), `block_type_metadata_settings` (settings after parse), `register_block_type_args` (any registration).

## Dynamic render

`render` file receives `$attributes` (defaults applied), `$content` (saved inner HTML / InnerBlocks output), `$block` (`WP_Block`). The file is included per instance: never declare functions/classes inside it.

```php
<?php // render.php
$count = max( 1, (int) ( $attributes['count'] ?? 3 ) );
$query = new WP_Query( [ 'posts_per_page' => $count, 'no_found_rows' => true, 'ignore_sticky_posts' => true ] );
if ( ! $query->have_posts() ) {
	return; // print nothing → block disappears
}
?>
<ul <?php echo get_block_wrapper_attributes( [ 'class' => 'is-layout-' . esc_attr( $attributes['layout'] ?? 'stack' ) ] ); ?>>
	<?php while ( $query->have_posts() ) : $query->the_post(); ?>
		<li><a href="<?php the_permalink(); ?>"><?php the_title(); ?></a></li>
	<?php endwhile; wp_reset_postdata(); ?>
</ul>
```

- `get_block_wrapper_attributes( array $extra = [] )` returns the escaped attribute string with block class, support classes/styles (colors, spacing, typography, align, anchor, custom className…). Merges `class`/`style`; call exactly once on the root element.
- Context: `$block->context['postId']` (declare `usesContext`). Inner blocks: `$block->inner_blocks`, raw: `$block->parsed_block`.
- Escape everything: `esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`. `$content` is already-rendered block HTML: echo as-is.
- Container dynamic block: JS `save` returns `<InnerBlocks.Content />` (or `useInnerBlocksProps.save`), PHP prints `$content` inside wrapper.
- Fully dynamic block JS: `save: () => null`. Markup changes then need no deprecation, only attribute schema changes do.
- `render_callback` signature (classic): `function ( array $attributes, string $content, WP_Block $block ): string` — must return, not echo.

Global render filters: `pre_render_block`, `render_block_data`, `render_block_context` (applies to all nested levels, 6.8), `render_block` / `render_block_{$name}` (`$block_content, $block, $instance`). Use `WP_HTML_Tag_Processor` to mutate HTML safely:

```php
add_filter( 'render_block_core/image', function ( $html, $block ) {
	$p = new WP_HTML_Tag_Processor( $html );
	if ( $p->next_tag( 'img' ) ) { $p->set_attribute( 'decoding', 'async' ); }
	return $p->get_updated_html();
}, 10, 2 );
```

Streaming parser for large content (6.9+): `WP_Block_Processor` scans block structure without full `parse_blocks()` allocation.

## PHP-only blocks (WP 7.0+)

```php
add_action( 'init', function () {
	register_block_type( 'acme/notice', [
		'title'           => __( 'Notice', 'acme' ),
		'attributes'      => [
			'message' => [ 'type' => 'string', 'label' => __( 'Message', 'acme' ), 'default' => '' ],
			'level'   => [ 'type' => 'string', 'label' => __( 'Level', 'acme' ), 'enum' => [ 'info', 'warning' ], 'default' => 'info' ],
			'count'   => [ 'type' => 'integer', 'label' => __( 'Count', 'acme' ), 'default' => 1 ],
			'dismiss' => [ 'type' => 'boolean', 'label' => __( 'Dismissible', 'acme' ), 'default' => false ],
		],
		'render_callback' => fn ( $a ) => sprintf( '<div %s>%s</div>',
			get_block_wrapper_attributes( [ 'class' => 'is-' . esc_attr( $a['level'] ) ] ),
			esc_html( $a['message'] ) ),
		'supports'        => [ 'autoRegister' => true, 'color' => [ 'background' => true ] ],
	] );
} );
```
- No JS needed: core passes auto-registered names to the editor (`window.__unstableAutoRegisterBlocks`, private) and renders via ServerSideRender; inspector fields (DataForm) are generated from `string`/`number`/`integer`/`boolean` attributes (+ `enum` → select). `label` = field label.
- A `block.json` with `"supports": { "autoRegister": true }` + `"render"` and no `editorScript` also qualifies (core only checks `autoRegister` + non-empty `render_callback`, and `render` creates one).
- Limits (per dev note): no `save`, no sourced attributes, no InnerBlocks, no media/rich fields; `role: local` and unsupported types get no control. Known bug: `usesContext` `postId` only on initial render (Gutenberg #78619).
- Choose it for simple server-rendered widgets; use JS blocks for rich editing UX.

## ServerSideRender (editor preview of PHP output)

Legacy/fallback: prefer real JS `edit` + REST data. When needed:
```js
import { ServerSideRender, useServerSideRender } from '@wordpress/server-side-render'; // named exports WP 6.9+
// default import is deprecated (needed only for WP ≤ 6.8)
<ServerSideRender block="acme/latest" attributes={ attributes } />
const { content, status, error } = useServerSideRender( { block: 'acme/latest', attributes } ); // 6.9+
```
Attributes must be registered in PHP (they are, via block.json). Endpoint: `/wp/v2/block-renderer/{name}`.

## Assets: hooks and scripts

| Target | Hook / API |
|---|---|
| Block's own JS/CSS | `block.json` fields (auto-registered, enqueued in the right contexts) |
| Editor UI (sidebars, plugins, JS variations/styles, filters) | `enqueue_block_editor_assets` (not loaded inside the canvas iframe) |
| Content in canvas iframe + front end | `enqueue_block_assets` (WP 6.3+; guard with `is_admin()` for editor-only) |
| Theme per-block CSS | `wp_enqueue_block_style( 'core/group', [ 'handle' => …, 'src' => …, 'path' => … ] )` |
| Theme editor CSS | `add_editor_style()` |
| Inline editor CSS | `block_editor_settings_all` → `$settings['styles'][] = [ 'css' => '…' ]` |

Translations: script fields auto-call `wp_set_script_translations( $handle, $textdomain )` when `textdomain` set. Script modules (WP 7.0+): translations auto-load only for domain `default`; plugins must call `wp_set_script_module_translations( 'acme-card-view-script-module', 'acme' )` (optional 3rd arg: languages path) after registration.

Script modules API: `wp_register_script_module( $id, $src, $deps, $ver, $args )`, `wp_enqueue_script_module( $id )`; deps entries may be `[ 'id' => '@wordpress/a11y', 'import' => 'dynamic' ]`. Server→client data (6.7+):
```php
add_filter( 'script_module_data_@acme/app', fn ( $d ) => $d + [ 'nonce' => wp_create_nonce( 'wp_rest' ) ] );
// JS: JSON.parse( document.getElementById( 'wp-script-module-data-@acme/app' ).textContent )
```
Classic script depending on a module (WP 7.0+): `wp_register_script( 'acme-legacy', $src, [], $ver, [ 'in_footer' => true, 'module_dependencies' => [ '@acme/app' ] ] )` — load in footer/defer or bare-specifier imports fail.

## Block-editor PHP filters worth knowing

- `allowed_block_types_all( $allowed, WP_Block_Editor_Context $ctx )` — whitelist per post type.
- `block_categories_all( $cats, $ctx )` — add categories.
- `block_editor_settings_all( $settings, $ctx )` — e.g. `disableContentOnlyForTemplateParts` (7.1), `responsiveEditingEnabled` (7.1).
- `get_block_type_variations( $variations, WP_Block_Type $type )` — server variations.
- `register_block_style()` / `unregister_block_style()` — see theme-json-and-styles.md.
- `hooked_block_types`, `hooked_block`, `block_bindings_*` — see bindings-hooks-variations.md.
- Registry: `WP_Block_Type_Registry::get_instance()->get_registered( 'acme/card' )`, `unregister_block_type()`.

## Post meta for blocks

```php
register_post_meta( 'post', 'acme_subtitle', [ 'show_in_rest' => true, 'single' => true, 'type' => 'string',
	'auth_callback' => fn () => current_user_can( 'edit_posts' ) ] );
```
`show_in_rest` is mandatory for editor access and bindings; keys starting with `_` are protected (no bindings). Read in JS via `useEntityProp( 'postType', postType, 'meta' )`; render from PHP with `get_post_meta( $block->context['postId'], … )`.
